# Top-down + Broker-Aware Decision Framework · 自上而下 + 券商上下文决策层

## 0. 目标

`trading-research` 每次判断不只回答“这只票好不好”，而要回答：**在当前新闻、政策、宏观四象限、内生市场结构、微观基本面、市场执行结构和 用户 的实际账户座位下，现在该不该动、动多少、错了怎么退出。**

这层框架是覆盖层，不替代华源/Serenity/威科夫/利弗莫尔/游资/因子/泊松/Gamma，而是决定它们的权重、仓位上限和证伪条件。

## 1. 用户 的默认投资使用习惯

| 模块 | 默认角色 | 使用边界 |
|---|---|---|
| Longbridge / 长桥 | 实时行情、盘前盘后、K线、交易时段、港/美/A跨市场行情、组合/持仓、可用时期权链 | 通过 **LongBridge CLI**（`~/.local/bin/longbridge`，`--format json`）取数；失败回退 AkShare、Yahoo、交易所/公告源 |
| AkShare（Python） | A 股短线结构（涨停/炸板/龙虎榜/资金流/连板）、港/美行情K线、南向资金、美债利率 | A 股主力数据源；eastmoney 推送域名需绕代理重试 |
| WindClaw / Wind | A 股实时表现、个股/板块、Wind 金融语料、公告/研报/新闻搜索 | 备用与交叉验证源；只在健康检查和实际调用成功时写已抓取；session 不进报告 |
| IBKR / 盈透 | 账户座位：持仓、均价、现金、购买力、保证金、币种、订单历史、期权持仓（仅当只读数据/导出可用） | 默认只读；没有已验证接口时不能声称已抓取；绝不提交真实订单 |

## 2. 九层决策栈

| 层级 | 核心问题 | 必查证据 | 对决策的影响 |
|---|---|---|---|
| 0. 输入/账户边界 | 这是新建仓、加仓、减仓还是复盘持仓？ | 用户给的持仓/成本；Longbridge/IBKR 只读账户上下文 | 决定输出“建仓计划”还是“持仓处理” |
| 1. 实时新闻/事件 | 过去 72 小时有什么改变胜率/赔率？ | Grok/X、WindClaw document/web、web_search、公告、财报日历、会议/发布会/监管节点 | 只把改变赔率的信息纳入决策 |
| 2. 政策/监管 | 顺政策还是逆政策？监管风险是否单向？ | 监管公告、产业政策、利率/关税/补贴/出口管制、交易所问询 | 政策逆风只能降仓 |
| 3. 宏观四象限 | 流动性、经济、通胀利率、情绪分别是什么状态？ | 见 `macro-dashboard-four-pillar.md` | 决定 attack / neutral / defend 及久期偏好 |
| 4. 内生市场结构 | 事件是火柴还是燃料？仓位/杠杆/被动资金/发行供给吗？ | 见 `endogenous-market-structure-playbook.md` | 决定是否追高、是否改做 pair trade |
| 5. 行业/产业链 | 行业景气度和供需瓶颈是否真实？ | capex、订单、交期、涨价、库存、竞争格局、南向/板块轮动 | 决定 Serenity/叙事/因子权重 |
| 6. 微观基本面 | 公司叙事能否被报表验证？ | 收入、毛利、现金流、应收、资产效率、guidance、估值 | 决定能不能持有/中线看多 |
| 7. 市场结构/执行 | 今天有没有合法座位？ | 量价、趋势、流动性、期权/Gamma、情绪周期、盘口 | 决定是否现在动 |
| 8. 券商执行约束 | 用户 真实账户是否允许这样动？ | 持仓集中度、现金/购买力、保证金、币种、未平仓期权、订单历史 | 决定实际仓位上限 |

## 3.1 杀杠杆 / 流动性踩踏六信号（Regime Override）

| 信号 | 代表什么 | 对动作的约束 |
|---|---|---|
| VIX 暴涨 | 波动率冲击、风险预算收缩 | 不把下跌先当均值回归 |
| 黄金与指数同跌 | 现金需求主导，典型流动性挤兑 | 暂停“避险腿有效”假设 |
| Apple / AAPL 暴跌 | 在卖流动性与领导股，不只是卖垃圾资产 | 下调指数托底预期 |
| 长端美债利率暴涨 | 折现率上行 + 股债对冲失灵 | 长久期与高估值资产降级 |
| Skew 极左 | 市场愿意高价买左尾保护 | 反弹先按 bounce 处理 |
| 指数 GEX 出逃 / 变脆 | dealer 缓冲减弱、墙位易下移 | Put Wall / Flip 优先于主观抄底 |

建议直接写成 `risk_regime`：`normal → stress_building → deleveraging_watch → active_deleveraging → forced_liquidation`。

## 3.2 四象限解释优先级

1. 先分桶，再合成，不允许一句“宏观偏中性”结束。
2. `流动性弱 + 情绪强`：先当估值/情绪行情，不给满仓追高。
3. `增长放缓 + 通胀降温`：有利久期，但若 liquidity 弱，只能反弹不等于大牛。
4. `AI productivity 叙事强 + 资源 capex 抬升`：允许“AI 利好利润，但通胀/利率仍不友好”。

## 3.3 内生市场结构 override

| 结构状态 | 典型信号 | 动作 |
|---|---|---|
| `uncrowded_constructive` | 叙事刚起、买方分散、没有明显供给 overhang | 可顺势 |
| `crowded_but_supported` | 很拥挤，但有业绩/被动承接/基本面兜底 | 持有但不追 |
| `fragile_crowded` | 利好不涨、同质 holder、多杠杆 | 先减风险/配对 |
| `unwind_active` | 破位 + 杠杆松动 + 事件触发 | 以防守为主 |

## 4. 仓位倍率规则

| 条件 | 仓位影响 |
|---|---|
| 四象限 = `attack` | 基础仓位 ×1.0 |
| 四象限 = `neutral` | ×0.6-0.8 |
| 四象限 = `defend` | ×0.2-0.5 |
| 杀杠杆信号 3 个以上 | 最大仓位 ×0.5 起步；暂停 L3 加仓 |
| `active_deleveraging` / `forced_liquidation` | 最大仓位 ×0.3 / ×0-0.2 |
| `fragile_crowded` | 加一层 `内生结构倍率 ×0.5-0.8` |
| `unwind_active` | `内生结构倍率 ×0-0.4`，优先等待 forced seller 出清 |
| IPO / secondary / lockup / mega financing | `流动性倍率 ×0.4-0.8`，确认吸收完再恢复 |
| 市场结构强但基本面证伪 | 只能作为短线交易，不得包装成长线 |
| 当前账户已重仓/集中度高/保证金压力高 | 即使信号强，也只能给减风险或等待回踩计划 |

## 5. Longbridge / IBKR 抓取与降级规则

### Longbridge 优先抓取
优先尝试行情、K线、盘前/盘后、交易时段、可用时期权链。报告只说明源是否可用，不能输出任何 token 值。

### IBKR 只读账户上下文
若用户要求按自己账户处理，优先读取或让用户提供只读信息：持仓、平均成本、当前盈亏、现金、购买力、保证金、币种、未平仓期权和订单历史。

未发现 IBKR 只读接口时：
- 不说“已抓取 IBKR”；
- 报告写 `IBKR account context unavailable`；
- 输出一般仓位上限，而不是账户级具体买卖数量；
- 如果账户上下文会显著改变结论，再向 用户 要只读导出或授权接入。
